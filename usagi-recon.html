月結沖帳自動化引擎

獨立復刻一套企業月結對帳（沖帳）工具：把會計人員手動判讀的邏輯，重建成一支 決策樹引擎，自動把每一筆訂單分類到 32 個會計科目。 以 Python＋JavaScript 雙引擎 實作並驗證輸出逐字一致， 跨 18 個月、約 19,000 筆 訂單逐筆核對。

問題

每月的訂單要跟發票、收款（ATM／信用卡／分期／貨到付款）、ATM 退款、折讓單一一比對， 判斷它屬於「應收、預收、沖銷、退款、折讓、作廢」等會計狀態——情境組合多達數十種， 過去仰賴人工逐筆判讀，耗時且容易出錯。目標是把這套判讀邏輯完全自動化， 並要能驗證到與既有工具逐筆一致。

做法

  • account_tree把領域邏輯抽象成 4 大情境 × 40+ 判斷分支 的決策樹（依發票 I／收款 P／ATM退款 R／折讓 D 四個變數分流）。
  • sync_alt用 Python 與 JavaScript 各寫一套引擎，互為對照，確保邏輯沒有語言相依的隱性差異。
  • fact_check建立逐筆比對驗證流程，跨 18 個月對帳，差異一筆一筆追到根因。

引擎的核心：四大情境決策樹

①

只有發票

有開發票、未收款 → 應收 / 作廢。

②

只有收款

先收款、未開票 → 預收 / 退款。

③

發票＋收款

兩者並存 → 沖銷 / 折讓 / 部分退款（最複雜）。

④

只有折讓

僅折讓單 → 折讓待退 / 異常。

verified工程亮點

  • · 雙引擎逐字一致：Python 與 JavaScript 兩套獨立實作，輸出（分類＋五大金額＋分頁）逐格相同。
  • · 逆向工程：比對中反向推斷出參考工具的「產表規則改版」，重建三個世代的版本切換。
  • · 根因分析：每一筆差異都追到底——分出哪些是程式 bug（已修）、哪些是來源資料瑕疵（如審計漏填）。
  • · 付款方式判讀：以實際付款記錄（而非發票欄位）推斷通路，修正多筆跨通路誤判。

insights成果

  • · 18 個月、約 19,000 筆訂單，13/14 月逐筆 result.txt 100% 對齊。
  • · 唯一未滿分的一筆，查證為來源資料漏填（審計補在總計），非程式邏輯問題。
  • · 把原本數小時的人工對帳，壓縮成一鍵數秒完成。
  • · 全程以 Claude AI 協作開發、驗證與重構。
